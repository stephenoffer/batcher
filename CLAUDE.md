# Batcher v2 — Engineering Contract

Batcher is a native, JIT-compiling, **adaptive** data engine: a Python control plane over a
Rust data plane on Apache Arrow, aiming to beat DuckDB, Spark, and Polars from
sub-second queries to PB-scale, batch and streaming, single-node and distributed.

The moat is **stage-boundary re-optimization on *measured* cardinalities** (`api/adaptive/`)
plus a **sketch-backed cross-query learned-stats and bandit loop** (`kyber/learning.py`,
`kyber/learned_tuning/`). **This is aspirational, not a description of today** — it is not
finer-grained than Spark AQE, and it is off by default below 20M rows.
`docs/internals/competitive_architecture.md` is the code-checked scorecard;
**read it before making a competitive claim, and never restore a claim it retires.**

## The non-negotiable invariants

MUSTs. A change that breaks one is wrong even if it compiles and your tests pass.

1. **Three independent subsystems.** `kyber`/`carbonite`/`core`/`governance` MUST NOT import
   one another. Only `api` imports them; `plan` is neutral. → `just lint-layers`
2. **Control plane vs data plane.** Python builds/optimizes a plan and ships it as JSON IR;
   it MUST NOT touch a tuple in the hot path. Per-row work lives in Rust.
3. **Arrow is the only columnar contract.** Every operator, tier, and the FFI boundary speak
   Arrow `RecordBatch`. Zero-copy across FFI. No bespoke row formats.
4. **Only `bc-py` links PyO3.** Every other crate `cargo test`s without a Python interpreter.
5. **The crate DAG points one way.** `bc-arrow → bc-expr → {bc-ir → bc-runtime, bc-codegen}
   → bc-interp → bc-py`, with `bc-sketches`/`bc-resource`/`bc-transport`/`bc-io` as leaves
   consumed higher up. Never an upward or sideways edge.
6. **One `Expr`, one `RelOp`, across tiers.** The Tier-0 interpreter is the correctness
   oracle; the Cranelift JIT MUST be bit-for-bit identical on its supported subset and
   silently fall back otherwise — **never diverge**.
7. **Single-node == distributed via mergeable algebra.** Stateful operators are
   `partial → combine → finalize`. No separate distributed semantics.
8. **The JSON IR is a stable wire contract.** Python `to_ir()` tags and Rust `serde` tags
   MUST change **in the same commit**.
9. **Everything is tested, correctness before speed.** Every relational/operator change adds
   a **differential test vs DuckDB**; Rust primitives keep seq == par == JIT.
10. **No performance regressions.** Perf work is benchmarked vs DuckDB/Polars.
11. **Python stays clean.** ruff-clean, fully typed, no duplication, no dead code, small
    curated public API with Google-style docstrings.
12. **Structure stays bounded.** Python ≤500 lines, Rust ≤800 (excl. tests), ≤12 files/dir,
    ≤5 levels, `__init__` ≤120 re-export-only. → `just lint-structure`

## Silent-failure guards — read these even if you read nothing else

Each of these has already happened here, and each one **passes every gate while being
wrong**. A mechanical check will not save you.

- **Never `import batcher._native`.** Always `from batcher._internal.native import engine`.
  The import graph cannot see into a compiled extension, so a direct import is attributed to
  the root `batcher` package — forging a phantom `core → batcher → api → kyber` cycle that
  breaks all six independence contracts. This is what broke them once already.
- **Run `just install-hooks` before you write any code.** It is the bootstrap for every other
  gate. A branch once shipped with the layer contract broken in all six directions and the
  size limits blown, purely because the hook was never installed.
- **A green gate is not a green light.** Every gate passed while `sort(descending=True)`
  returned unsorted data under spill, and while a distributed `GROUP BY` on a float key split
  one group in two — because nothing *combined* an operator with a non-default flag on a
  non-default path. Test the cross-product: `{collect, spill, iter_batches, distributed}` ×
  `{nulls, empty, one row, duplicates, -0.0/NaN, descending}`
  (`tests/differential/test_diff_operator_matrix.py`). **And never assert a sort with an
  order-independent comparison** — `assert_same` is order-independent by design, so reaching
  for it is exactly how a sort bug stays invisible.
- **The size limits are subordinate to the invariants.** If satisfying `lint-structure` would
  cross a layer, fork the wire contract, or break the crate DAG, **the invariant wins**:
  leave the file oversized and add it to `STRUCTURE_ALLOW` with a one-line reason. The
  checker is the thing pushing you the wrong way here; it cannot detect this.
- **Never weaken or delete a differential test to make a change pass.** It is the most
  tempting move under a red gate and the most damaging. If Batcher and DuckDB legitimately
  differ, surface that explicitly as a decision.
- **Core measures, Kyber decides, Carbonite protects.** A Kyber pass that collects runtime
  metadata, or a Core path that makes an optimization decision, compiles and passes tests
  while quietly corrupting the feedback loop that makes plans improve across runs.
- **A stateful operator without a mergeable form** works perfectly single-node, passes every
  local test, and silently caps the operator at one machine. Failure appears at cluster
  scale, as wrong results rather than an error.

## Repository map

Grep **`MAP.md`** for the file-level index and the "where does new X go" routing table. If you
cannot find a home for new code there, **stop and ask — do not invent one.**

```
python/batcher/     Control plane — never touches a tuple in the hot path
  ml/ _sql/    front-ends ON the public API (ML/inference/loaders; SQL parser)
  api/         conductor: the ONLY layer importing the subsystems
  dist/        distributed *scheduling* (Ray tasks, Flight shuffle, spill)
  kyber/       optimizer (plan → plan)   carbonite/  resources, spill, credits
  core/        executor + adaptive loop  governance/ row/column policy as a rewrite
  io/ observe/ plan/ metadata/           NEUTRAL — importable by anyone
  config/ _internal/   `_internal.native` is the ONE engine accessor
crates/             Data plane — pure Rust + Arrow (only bc-py links PyO3)
  bc-arrow Morsel(16,384) · bc-expr the one Expr · bc-ir the one RelOp
  bc-runtime mergeable agg/join/shuffle/window + `keys` (the ONE key identity)
             — NOT sorting: every sort lives in bc-interp::ops
  bc-codegen Cranelift JIT · bc-interp Tier-0 execute/par/dist + sorts + spill
  bc-sketches · bc-transport (Flight; bypasses the Ray object store) · bc-resource
  bc-io · bc-udf (NOT wired into bc-py — not on a live path) · bc-py (FFI)
```

## Gate before "done"

Nothing is done until the gate is green. Run what your change touches:

| Changed | Run |
|---|---|
| Any Rust | `just check` → `just test-rust` → `cargo clippy --workspace --exclude bc-py --all-targets -- -D warnings` → `cargo fmt --all` |
| Any Python | `just lint-py` → `just lint-layers` → `just lint-structure` → `just build` → `just test-py` |
| FFI surface or IR tags | **both** of the above (the two sides must move together) |
| Public API | `just lint-docstrings` + `just docs` |
| Any test | `just lint-tests` — an ordered result compared unordered, or an assertion true by construction, fails the build |
| Docs / agent guidance | `just docs` + `just lint-guardrails` |
| Anything perf-relevant | `just bench` (+ `bench-ops` / `bench-dist`) |
| Moved or renamed a file | `just map` + `just lint-guardrails` + `just surface-diff` |

`just` also has: `build`, `build-release`, `test`, `fmt`, `map`, `surface-save`/`surface-diff`,
`install-hooks`. The `/run-quality-gate` skill walks the full sequence and triages failures.
